# Как со мной работать на этом проекте

Контекст у меня уже есть: `CLAUDE.md` (паттерны), `ROADMAP.md` (план фазами + открытые вопросы), `prisma/schema.prisma` (БД), плюс эталонные модули `UserModule` и `OnboardingModule`. Этого хватает, чтобы получать готовые куски кода — главное правильно ставить задачу.

## 1. Базовая структура хорошего промпта

```
<что делаем> → <в какой фазе/файле ROADMAP это> → <ограничения и решения> → <как проверить>
```

Плохо: «сделай авторизацию».
Хорошо: «Phase 1.3 — `LoginCommandHandler` в `src/modules/identity/auth/`. Использовать `argon2.verify` (пока inline, `PasswordService` отдельным шагом). Вернуть `{accessToken, refreshToken}`. Refresh-token model в БД ещё не заведена — пропусти, верни заглушку с TODO. После: `pnpm build` и покажи diff».

Почему так:
- **Ссылка на фазу/файл** — я не гадаю про область, иду в нужное место `ROADMAP.md` и `CLAUDE.md`.
- **Явные решения** — половина задач блокируется «открытыми вопросами» из конца ROADMAP. Если ты их не зафиксируешь в промпте, я либо спрошу (плюс ход), либо угадаю (минус ход).
- **Условие проверки** — заставляет меня не «кажется работает», а действительно собрать.

## 2. Какие команды и слова реально помогают

- **«По образцу X»** — самое сильное. «По образцу `OnboardingTemplateEntity` собери `CourseEntity` с детьми Modules». Я возьму конкретный файл как референс, а не «общий стиль DDD».
- **«НЕ трогай Y»** — защищает от рефакторинга соседнего модуля. У меня есть склонность чинить смежные баги по дороге, особенно `this.prismaService.client` → `this.db`. Если не нужно — скажи.
- **«Только план, без кода»** или **«EnterPlanMode»** — когда хочешь сначала договориться об архитектуре. Для крупных штук (Phase 4 Course-агрегат) это обязательно — иначе я нагенерю 10 файлов в неправильную сторону.
- **«Сначала задай вопросы»** — если задача мутная, я сразу спрошу через `AskUserQuestion` вместо домыслов.
- **«Зафиксируй в `ROADMAP.md`/`CLAUDE.md`»** — после крупного изменения попроси отметить `[x]` и обновить шапку. Иначе следующая сессия не узнает, что сделано.

## 3. Размер задачи

Оптимум — **одна use-case-папка за раз**. То есть: один command + handler + (если нужно) DTO + регистрация в module. Это ~5 файлов, я их делаю целиком за один проход и могу проверить `pnpm build`.

- Меньше (один файл) — теряем эффект сессии, много рутины.
- Больше (целый модуль за раз) — я начну торопиться: эпизодически пропущу `import type`, ошибусь в порядке аргументов `ApplicationException`, забуду зарегистрировать handler в `providers`. Это всё всплывёт на `pnpm build`, но дороже.

Исключение — **скаффолдинг**: «прокинь пустые скелеты для всех CRUD-команд `EmployeeModule`» — тут много, но шаблонно, ошибиться сложно.

## 4. Что я считаю «по умолчанию» — не повторяй

Эти штуки уже зафиксированы в `CLAUDE.md`, не пиши их каждый раз:

- DDD-слои (`domain/application/infra/presentation`), Entity с `create`/`recreate`, `Mapper` с тремя методами.
- Command/Query через `CommandBus`/`QueryBus`, `import type` для портов, `Symbol` DI-токены.
- `class-validator` для request DTO, классы из `libs/api/dto/` для response.
- Read-side handlers могут идти в `PrismaService` напрямую.
- `ApplicationException` для use-case-ошибок, `DomainException` для инвариантов.
- `repo.transaction(async () => …)` для атомарности, репозиторий читает через `this.db`.

Если хочешь от этого отступить — скажи явно («сделай тут без транзакции, ок»), иначе я буду следовать паттерну.

## 5. Паттерн фаз — как реально дойти до готовой системы

Фазы в ROADMAP упорядочены по блокировкам. Я бы шёл так, и тебе советую тем же путём ставить задачи:

1. **Phase 0** — мелкими PR-ами. Один промпт на `EnvSchema`, один на `userId` в контексте, один на замену `throw Error` в onboarding. Это всё короткие задачи.
2. **Phase 1** — самая важная и самая опасная. Сделай **сначала план** (отдельным промптом: «спланируй token + refresh rotation, не пиши код»), договоримся, потом по разделам 1.1→1.6. Без этого все остальные фазы будут переписываться.
3. **Phase 2.4 (доделать User), Phase 5 (доделать Onboarding)** — параллельно после Phase 1. Это «доводка», не блокирует ничего нового.
4. **Phase 2 (org/people)** — здесь много CRUD-однотипного, можно скаффолдить большими кусками.
5. **Phase 3, 4, 6, 7** — по приоритету фронта. До Phase 4 решить «открытые вопросы» №1–4 из ROADMAP, иначе придётся переделывать.

После каждой фазы — **один промпт «обнови ROADMAP.md и CLAUDE.md по факту сделанного»**. Это критично: без этого следующая сессия не будет знать состояние.

## 6. Когда я ошибаюсь — типичные кейсы

- **Перепутаю порядок `ApplicationException(message, statusCode, code)`** — проверяй по логам/в коде, я и в этом промпте про это писал, всё равно ошибусь.
- **Забуду зарегистрировать handler в `providers`** module — увидишь на старте Nest, не на build.
- **Сделаю `this.prismaService.client.user.*` вместо `this.db.user.*`** — техдолг уже в `UserPrismaRepository`, я могу повторить.
- **Не импортирую `type` для порта** — `pnpm build` сразу ругнётся TS1272.
- **Создам файл там же, где хочется, а не там, где паттерн** — особенно для DTO. Если сомневаешься где-то будет файл — спроси «куда положишь?».

Лучшая защита — заканчивать промпт фразой **«покажи diff и подтверди что `pnpm build` зелёный»**. Я тогда обязан реально собрать.

## 7. Чего НЕ просить меня делать

- **Дизайн БД с нуля** — `prisma/schema.prisma` уже описан целиком. Поправки точечные, через `pnpm prisma migrate dev --name <…>`.
- **Решать «открытые вопросы»** из ROADMAP за тебя (Course-агрегат целиком vs нет, soft/hard delete сотрудника, MinIO vs локальный диск и т.д.). Я предложу — но коммитить решение должен ты, иначе оно потеряется.
- **Запускать что-то опасное** (миграции на проде, force-push, `--no-verify`) без явной фразы «да, давай».
- **Писать тесты, не имея договорённости о стратегии тестов** (Phase 7.1 — там три варианта: unit/integration/e2e). Сначала договоримся, потом тесты.

## 8. Минимальный шаблон промпта на каждую задачу

```
Phase X.Y из ROADMAP.
Задача: <одно предложение>.
По образцу: <путь к похожему модулю/файлу>.
Решения: <если задеваешь открытый вопрос — зафиксируй ответ>.
Не трогай: <смежные модули, чтобы не было «попутно починил»>.
Проверка: pnpm build (+ pnpm test если есть spec).
После: обнови ROADMAP.md (отметь [x]).
```

Если будешь держать этот скелет — за условные 15–20 сессий я закрою все 7 фаз. Без скелета — будет в 2–3 раза дольше, потому что половина времени уйдёт на переделки.
